# Native SSR/Browser fixtures

`build.sh` compiles each admitted case with this checkout, renders paired typed SSR and explicit Browser documents through `forma-server`, and stores each real `PageResponse` header beside its HTML. `serve.mjs` replays those headers unchanged. The root Playwright configuration runs Chromium; release qualification may supply the same configuration with all three engine projects.

The fixture is served over HTTP, so its `RenderCtx` names `PolicyExtensions::report_uri("/__csp-reports")`. Both policies retain Trusted Types; the extra debug Report-Only policy now has a real destination. The receiver bounds each body to 64 KiB and stores at most 1,024 normalized reports, preserving only document pathname, effective directive and disposition (explicitly `null` when a legacy WebKit report omits it; invalid present values are refused). Append-only cursors and unique control document paths avoid resetting another parallel test's evidence. It stores no sample, query, fragment or raw body.

`csp-reporting.spec.ts` serves a second local origin, proves it is reachable, then requires native CSP to prevent an image request to it while delivering both a browser violation event and a real HTTP report. This intentional violation is separate from the positive cases, whose console/page/activation error observers remain strict. No external network is used. Receiver bounds and normalization run under `scripts/ssr-csp-reports.test.mjs` in `scripts/check.sh`.

The browser control proves enforcement from `securitypolicyviolation.disposition` and the absence of any request at the reachable local image origin. Its separate HTTP delivery assertion requires the exact unique document path and directive. It does not invent a missing legacy report disposition. The actual first WebKit request was captured outside the receiver before this schema correction.
