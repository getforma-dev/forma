The full core artifact retains every structured probe report and process result,

That mechanical replay did not prove its three declared equivalence exemptions.
A separate semantic audit found that removing the undefined-style guard can erase
inline styles through `cssText`, while the two list-algorithm thresholds differ
for `NaN` keys. All three exemptions have been removed without changing the
328 probe IDs, order, targets, anchors, replacements or tags.

The style guard remains correct production behavior. Its new, isolated regression
test checks preservation of the complete style attribute, including `!important`
and opacity, when `cssText` is undefined. The corrected three-probe supplement
uses the unchanged canonical harness and original mutation definitions on
`dbfb67fffb2f6cf6049b513bf1876c274edd558a`. It catches the removed style guard
through the new assertion; both threshold variants survive. Clean before and
restored baselines each pass 4,216 tests with identical identities and states,
without an unqualified result. All 4,556 tracked snapshot files are restored
byte for byte. The source-bound composite is **326/328 caught (99.39%; 99%
under the canonical integer rounding), two survivors, zero equivalents and zero
unqualified probes**; expressions remain **98/98 (100%)**. Both unchanged 85%
floors pass. The three-probe subset alone scores 1/3; it is not compared with a
global floor in isolation. The independently verified supplemental receipt has
SHA-256 `3f25967c06e8feab9104fa6262e7275d32a277bd66d30095791f611739766009`.

The list finding is a medium-severity historical lifecycle defect, reproduced in
both the authenticated published 3.0.0 standalone package and current bytes:
repeated small-list updates with a `NaN` key can leave effects running after row
removal and root disposal. The maintainer's delegated release decision is to
retain the qualified implementation, disclose the issue and workaround in the
[upgrade guide](../UPGRADING-3.1.md#repaired-nan-keys-in-component-lists), and
track the repair as FORMA-290. It is nonblocking for 3.1 because the reproduced
behavior is unchanged from the published predecessor, not because `NaN` was
retroactively excluded from the public API. The two threshold probes remain
coverage gaps and must count as survivors rather than equivalents.

The source-bound repair retains every prior production, dependency, harness,
configuration and test input. The only executable addition is the isolated style
test. The original 325 catches and 98 expression catches are retained by that
comparison; the supplemental run supplies the new style catch and the honest
list-threshold classifications. This is a composed qualification, not a claim
that all 328 probes were rerun on the later source. The harness restores each
mutated source in a synchronous `finally` and checks its final baseline; the
original full artifact does not independently record per-probe before/restored
source-byte hashes.

## Regression audit of the measured paths

The independent 2026-10-25 audit compares actual emitted files, not ancestry
alone. All 16 files in the four default production/development ESM/CJS entry
graphs match the measured `9ac07a44` candidate byte for byte, with the same
`alien-signals@3.1.2` dependency. The standalone bundle differs from that retained
build only in two generated source-path comments; it exactly matches the selected
bundle in adoption run 40146688695. These comparisons support retaining the
recorded default-client results without a new race solely for later HTML-runtime
changes. Thirteen separate HTML-runtime output files do change.

All nine DOM and nine reactive workloads remain in the audit, including losses.
Selection is 1.36 ms against published 0.68 ms and previous-main 1.58 ms; clear is
6.00 ms against published 6.04 ms and previous-main 4.60 ms. Neither a favorable
aggregate nor the HTML-runtime repair erases the documented batching, adoption,
update and delivery costs. The 8,498 B Brotli application is 154 B smaller than
published but 81 B larger than the improved main. Small timing differences and
outliers are retained without being declared independent causal effects.

Server component evidence is similarly bounded. Combined static/walker changes
reduce 100-row HTML by 48.32%, but paired Sprint throughput improves only 3.74%;
1,000-row throughput is 0.10% lower and single-connection p99 is worse. The
combined source remains within its recorded memory, boot and image budgets.
Compression is opt-in: its smaller response trades away throughput and increases
tail latency and memory. Historical server images and strength measurements are
not represented as fresh measurements of the final 3.1 image.

The lazy-host repair has a separate, local six-leg interleaved diagnostic on the
changed HTML-runtime path. It removes the observed eager-allocation slowdown on
that workload. It does not establish statistical equivalence, population tails
or unchanged cost for every expression: the first access to a magic still creates
its branded host. Current packed correctness, startup observations and focused
identity tests provide separate checks. No newly unreported discrepancy in the
measured default-client path was found.
