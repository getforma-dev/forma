# 3.0 release gate dispositions

These entries reconcile the release contract with the founder's recorded
decisions. They do not assert that beta, RC or final qualification has passed.
Every remaining `pending` gate continues to block its milestone and later ones.

## Repository scope (L-57, 2026-10-15)

The release work stays in `getforma-dev/forma`: R17, both create-app templates,
the blocking parity corpus, internal fixture applications and P17. The external
application builds (FORMA-192) and login spike (FORMA-147) are informational,
not release gates. They have not been run as part of this task, and no application
repository is touched. Their explicit `not-run` records remain in the contract
outside `milestones.*.gates`; they are not reported as passed tests.

The real seven-day RC soak on `next` remains required. After the final release
and the v3 as-built design record, this programme halts before application work.

## Founder decisions (FORMA-146; L-57, 2026-10-15)

The founder confirmed Q10–Q13: reserve the state block's `s` field without adding
a shared-store mechanism in 3.0; keep `renderBoth` internal to Forma; use the
Lighthouse mobile profile and the recorded development machine as references;
and refuse startup when a page module is invalid. Q14–Q18 defaults were also
confirmed. This closes the recorded-decision gate, not the implementation or
measurement gates. Application hosting remains outside this release task.

## Alias warning and documentation are separate work

FORMA-141 is the `formaAlias` migration warning, implemented in `76df14bf` and
merged through independently reviewed PR78. It warns once per build, lists each
legacy importer, includes erased TypeScript imports and re-exports, preserves
mapping through 3.x, and stays quiet for strings/comments. Without the alias, an
unresolved bare import still fails. The build tests in
`packages/build/tests/alias-warning.test.ts` cover those cases; the accepted
integration CI also runs them.

The previous release contract incorrectly assigned the upgrade guide and
stability record to FORMA-141. Those obligations remain open under
`FORMA-145 documentation` until the final public surface is documented and
reviewed. No documentation acceptance is inferred from the alias tests.

## Size policy (L-59, 2026-10-15)

The founder explicitly approved N2 = 28,000 bytes gzip -9 of Forma code per
route after the indexed-list route measured 27,724 bytes against the prior
27,500-byte limit. Exact boundary acceptance/refusal and all other size and
performance gates remain enforced. The decision changes only N2; it does not
waive a failed performance measurement or authorize retagging.
